# Simpler hypothesis: a central-location price premium

Prespecified 2026-10-16, before downloading and inspecting listing prices. This is a separate experiment; prior RECS artifacts remain unchanged.

Hypothesis: otherwise similar short-term rental listings have higher nightly asking prices closer to central London. Access to jobs, transport and visitor attractions is capitalised in accommodation prices. Competing explanation: central listings differ in size, quality and host professionalism; local neighbourhood appeal can also matter independently of distance. This is an association, not a causal effect of moving a listing.

Source: Inside Airbnb, September 17, 2026 detailed London listings. Unit: one listing in one snapshot. No repeated snapshot inflation. Public free download, CC BY 4.0, provenance is scraped Airbnb advertisements, not completed transactions. Do not call the price realised rent, revenue or occupancy.

Target: log positive listed nightly price in local currency. Keep positive observed prices, valid coordinates and host IDs; use prices £10–£2,000 for the primary ordinary-rental cohort, with that restriction explicitly reported. Do not choose cutpoints after looking at results. Sensitivity: all positive prices, without modifying fitted models; evaluate how outliers change reported errors. Require capacity at least 1 and room count attributes may be missing rather than dropping observations. No restriction to professionally managed listings or a narrow subgroup.

Split: random disjoint host groups (seed 20261016): 60% training hosts, 20% validation hosts, 20% final test hosts. Multiple listings by the same host stay together. The split evaluates unseen hosts in the same snapshot; it is not a future-time test. No row randomisation that places one host in both sides. All preprocessing fitted only on training rows.

Physical/quality input group P: capacity, bedrooms, beds, bathrooms, room/property type, amenity content, host tenure/status/response policies, minimum/maximum booking rules and displayed review counts/ratings. Exclude IDs, URLs, names/descriptions with addresses, host location text, neighbourhood text, coordinates and postcode from P; exclude derived occupancy/revenue estimates, calendar availability, scraped target summaries, and review_scores_location (a direct location rating). Missingness retained. Raw category levels and amenity dummies are not counted as independent raw columns. Report true structured-column counts and amenity content separately.

Location group L: latitude/longitude, official neighbourhood and distance from a prespecified fixed central point (51.5074 N, -0.1278 E, central London). Compare P with P+L. Secondary interpretable regression uses P plus distance, excluding neighbourhood and coordinates so the distance term has a clear city-level interpretation. Longitude/latitude may be rounded/noisy. A single centre is a deliberate simple approximation, not a complete urban model.

Models: median log price; regularised linear regression (Ridge, alpha 1/10/100); small tree (depth 5, minimum leaf 50); random forest (200 trees, max depth 14, min leaf 10); XGBoost (depth 3 or 5, 300 trees, learning rate .05, min_child_weight 20, subsample .8, colsample .8, lambda 10). Tune only Ridge/XGBoost on validation MAE in log price. Use identical candidate grids for P and P+L. No holdout tuning or search across alternative hypotheses.

Primary prediction metric: mean absolute log-price error. Also report GBP MAE and R² in log price. For an illustrative pricing tool, >=5% relative reduction in log error from adding L is the declared practical signal that location matters. It is not an estimated business-profit threshold. Quantify a 5 km distance difference in the simple regression and use paired bootstrap confidence intervals clustered by host (1,000 draws; fixed fitted models). Distance association should be negative, its host-cluster interval below zero, and P+L should materially improve test prediction to support the proposed project. Do not substitute feature importance for these tests.

Read the dictionary and check shapes, duplicate IDs, target missingness, scrape dates, unique hosts, sample exclusions and useful inputs before fitting. Do a focused prior-work screen; no novelty claim from an unsuccessful short search. Report the simpler claim even if rejected; do not keep changing definitions to force support.

## Schema clarification before any fitting
The actual September file has 90 columns (the public dictionary describes an older version). Numeric bathrooms is entirely missing; parse the count and sharing indicator from bathrooms_text. The price matches the rounded nightly quote for 59,761 rows; these quotes cover different requested booking dates. Add booking-date context (check-in month/weekday, stay length, lead time, scrape day) identically to every model, since these dates would be known when quoting a stay. Never use quote amounts, raw quote payloads, estimated revenue, review_scores_value or review_scores_location as predictors. Those amounts copy the target, and value/location scores risk circular interpretation. Missing quote dates are retained explicitly.

Also fit a distance-only addition P+D alongside P+L, using the same fixed grids, to distinguish the simple centre-distance hypothesis from the larger location group. The primary practical threshold remains the full-location comparison; report distance-only results even if weaker. The interpretable regression is unpenalised log-price on training-only processed P and distance (ordinary regression with a host-cluster uncertainty interval). The regression describes the development sample; unseen-host ML errors provide the separate prediction test.
The schema audit also found the old host_since/response fields empty in this release. Host tenure uses the available years-plus-months-as-host pair, combined into one duration. Empty response fields do not count as predictor richness. This source adaptation was made before reading fitted model scores. The full positive-price sensitivity uses the same holdout host IDs and unchanged fits; it cannot assess tail-only hosts without a main-cohort split assignment.
Computation note before score inspection: the initial run was stopped during random-forest training because sparse tree splitting was slow. Trees/forests now receive the same processed numbers as a dense matrix; model grids, splits and hypothesis are unchanged. Initial logs are retained. No final holdout result from the interrupted runs was inspected or used for a decision.
